- `holdings_after_2026-11.csv`：2026-11 換股（11/12 開盤）後的策略持股（100 萬比例縮放的回測持股＋新買 1802），0050 共 5,965 股、其中底倉 1,995 股。
- `cash_after_2026-11.txt`：同一時點的策略現金 **12,126 元**（2026-11-16 稽核更正：原本寫「現金約 0」是錯的）。
  - 原因：換股後持股是用訊號日收盤估的，沒有照成交日開盤重算；賣出股開盤都比收盤高，賣出實得較多，照上面的股數會剩約 12,126 元現金（研究中心嚴成本）。
  - 照 11/12 開盤重算，1802 應為 882 股（計 0.3% 滑價為 880 股）、0050 應為 6,067 股；**上線起點沿用已發布的股數（1802 862 股、0050 5,965 股），不改**，差額以現金記在這個檔。
  - `build_site_data.py` 會自動讀同月份的 `cash_after_YYYY-MM.txt`（和 `holdings_after_YYYY-MM.csv` 放同一個資料夾），計入 live.json 的策略淨值（起點和每日都加上現金）。
  - 出處：`research/tw_stock_selection/agents/audit_live_2026-11/AUDIT_REPORT.md` 問題 3、audit.json 的 `cash_left_implied_by_state`。
- 下次（2026-12）產生名單：
  `python3 -I -B research/tw_stock_selection/agents/s18_live_list/live_surge/make_list.py list --month 2026-12 --holdings xq_scripts/site/state/holdings_after_2026-11.csv --cash 12126 --base-shares 1995 --repo research/tw_stock_selection/raw/jb7k6295r7-bot_tw-stock-data --repo <暫存>/tsd --out-prefix research/tw_stock_selection/agents/s18_live_list/lists/2026-12_strategy`

- 回測淨值與逐年（profit.json）：`python3 -I -B xq_scripts/site/make_profit.py`（2026-11-17 起預設讀 `xq_scripts/site/navs_official.csv.gz`＝正式數字（除權息＋期限修正），由 `research/tw_stock_selection/agents/official_nav/run_official.py` 產生；只修除權息的 `navs_exright.csv.gz`（exright_engine_fix/run_engine.py 1）與修正前的 s19 navs.csv.gz 保留，可當第一個參數給；XQ版用統一後換股日；0050 用精確含息還原價，不用 navs 的整數欄；週標籤＝當週最後一個交易日）。
- 網站資料：`python3 -I -B xq_scripts/site/build_site_data.py <月份 csv> <策略持股 csv> <月份 json> xq_scripts/site/profit.json <今天> <下次訊號日> <下次執行日> xq_scripts/site/data [<官方日K倉庫> <換股後持股 csv> <上線起始日>]`（後三個參數讓 holdings 加股數、起始價與 0050 一列，並產生 live.json；持股表「本月以來%」＝最新收盤 ÷ 起始價 − 1，換股清單 actions 的欄位叫「訊號日以來%」＝對訊號日收盤）
- **持股頁完整交易資訊（2026-11-18 起；後三個參數有給時才有）**：
  - **帳戶口徑**：策略模擬帳戶，起始日（2026-11-12）開盤＝100 萬元。持股檔股數在那天開盤連現金是 917,733 元，不是剛好 100 萬（live.json 一直把它正規化成 100 萬）。
    所以金額欄一律＝持股檔股數 × 換算倍數（100 萬 ÷ 917,733.4＝1.089641）× 價格；「股數」欄仍是持股檔原始股數，「帳戶股數」＝股數 × 換算倍數（四捨五入到整數股，只供閱讀）。百分比不受影響。
  - **holdings 新欄位**：列別（個股／0050／現金／合計）、帳戶股數、成本金額（× 起始價）、最新市值（× 最新收盤）、損益金額、損益%、占總資產%、
    季線價位、距季線%、試算名次、試算基準日、目前狀態、出場條件、本月交易、備註。另加「現金」「合計」兩列（代號欄就寫「現金」「合計」）。
    - 逐列金額四捨五入到元並調整到加總剛好等於合計列；合計列最新市值必須等於 live.json 最後一天的策略淨值，個股＋0050＋現金＝合計、各列損益加總＝累計損益，**不一致就報錯、不寫檔**。
    - 季線價位、距季線%、試算名次、目前狀態：直接呼叫名單產生器 `make_list.py` 的 `compute()`／`held_status()`（策略 E0 的還原收盤口徑，和前 20 名表的「距季線%」同一段程式）。
      程式先在訊號日重算一次、和名單的前 20 名與距季線逐檔比對（不同就報錯），再把日期換成最新一天。季線價位＝最新收盤 ÷（1＋距季線）。
    - 名次＝訊號日名次（月內不變）；試算名次＝同一份營收分數（名單的截止版），只把股價、季線、股池換成最新一天重排，季線下的股票不列入排名（空值）。下次訊號日會改用新月份營收。
    - 目前狀態＝試算「若今天就是訊號日會不會被賣」：續抱／會賣：跌破季線／會賣：跌出前 20 名／會賣：其他原因。**只是試算**；出場只在換股訊號日收盤檢查，平常跌破不賣。
    - 0050 列：底倉＋閒置資金，出場條件寫「不適用」；本月買賣股數取自名單 json 的 plan.e50（以訊號日收盤估算）。
  - **status 新欄位**：帳戶起始日、起始資金、目前總資產、累計損益金額、累計損益%、個股檔數、個股市值合計、0050市值、現金、同期只買0050總資產、同期只買0050損益%、
    領先0050_個百分點、下次換股檢查日、下次換股執行日、下次檢查條件、試算基準日、試算會賣檔數、試算說明、帳戶換算倍數、持股檔起始日開盤總值。
  - **actions 新欄位**：股數（賣出＝名單的持有股數；續抱、買進＝持股檔股數）、帳戶股數、成交日、成交價（執行日官方日 K 開盤價）、金額（100 萬帳戶口徑，未扣費用）、備註。
    續抱沒有買賣，成交日、成交價、金額是空值。賣出各檔的買進成本與已實現損益：資料不足（state 與 lists 都沒有），沒有填。

  - **頁面（`index.html`，2026-11-18 本機已改、尚未上傳發布）**：欄位仍是寫死的（表頭與 `fillTable` 欄位清單），資料加新欄位要一起改頁面。目前頁面有：

## 實際下單方式與逐筆對帳（2026-11-16，S37 執行研究）
- 換股日隔天 08:30～09:00 送**整股 ROD 限價單**參加 09:00 開盤集合競價（＝回測成交價）。
- 買進限價掛「**漲停價下一檔**」；賣出掛「**跌停價上一檔**」。集合競價是單一價格成交，掛寬不會成交更差。
- 開盤漲停買不到：**當天放棄，09:00 開盤沒成交就立刻刪單**（ROD 單會繼續掛著，盤中打開時會在高價成交，那不是回測的做法），不追、不補（10 年約 4 次）。開盤跌停賣不掉：同樣**立刻刪單**，隔天開盤再掛。（S37 已獨立複製確認）
- 零股不參加整股開盤集合競價，盡量用整股；零股另記一列。
- 每筆記在 state/fill_log_template.csv 的格式（45 欄）；每月研究中心用「成交價相對開盤」算實際滑價，三個月平均每邊 > 0.3% 就調整回測預期（每多 0.1% 約 −0.9 個百分點／年）。
- 資金 3,000 萬以上要分日下單，回測不能直接套用。

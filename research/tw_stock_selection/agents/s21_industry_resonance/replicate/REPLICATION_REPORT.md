# S21 產業共振：獨立複製報告

## 結論：成功

所有預先登記、決定判定的數字都重現了，和原研究**完全相同**（差值 0）。我自己重選凍結規則，同樣是 SWAP_P2。判定同樣是「不通過」：T0 和 V1～V4 五條都沒過，每一條的通過與否也和原研究一樣。

只有事後描述的「隨機換股對照」數字不同。原研究沒寫隨機抽樣的細節和種子，這一項本來就重現不了逐位數字。我抽了 200 次確認：原研究的 16／20 落在合理的抽樣範圍內，結論方向一致，不影響判定。

事前判定標準：年化差 ≤ 0.3 個百分點、回撤差 ≤ 0.3 個百分點算一致，而且判定（通過／不通過）必須相同。全部必要項都符合，所以結論是「成功」。

## 方法（獨立性）

- **沒碰原研究的程式**：沒有 import 或執行 s21lib.py、train.py、validate.py、posthoc.py，也沒有讀它們的內容。規則只依 PREREG.json 的文字和 FINDINGS.md 的條件。
- **自己寫的部分**：
  - PIT 產業查表：訊號日當天有效的那一段，start ≤ 日 < end；「未分類」當缺值。
  - 共振特徵 PEER／BRX／MKT／REL。
  - 6 條規則加 1 條「全部通過」驗收規則的名單產生：自己寫訊號迴圈，每列 F1 都 assert 和 make_signal_s10 相同。
  - 路徑、配對差、選規則、V1～V4、隨機對照。
- **共用引擎**：import s20lib → s17lib → s10lib。用到的有 make_signal_s10（只用來取 E0 出場矩陣、info，並核對 F1）、simulate_s10、e50_fix_suspension、seg_dd、top5_share，以及 s2lib.block_from（禁買最賺 5 筆）。
- **解讀校準**（第 0 步，還沒算任何報酬）：「同業有 SURGE 者 < 5 家」解讀為含自己 < 5 家；RANK_BR 的 BRX 名次同值取平均名次。用這組解讀，和 data_check.json 對照全部一致：
  - 6 條規則在訓練期、驗證期的改動檔數（剔除數、加入數、改動月份數）全部相同；
  - 各年 1 月的股池家數和 SURGE ≥ 2 比例相同；
  - F1 的 PEER 分布、BRX 分位數、BRX 缺值率 1.43% 相同。
  - 其他解讀不符：BRX 名次改用 min、first、dense，RANK_BR 的改動檔數都對不上；門檻改成不含自己 ≥ 5，BRX 缺值率對不上。
- **資源**：一律 python3 -I -B。主程式約 26 秒，峰值記憶體約 1.54GB（第 0 步核對 2.48GB，含第一次建面板快取）。暫存放 scratchpad/s21rep/，結束已刪除。

## 差異原因

1. **判定用的數字**（T、V、A、C 各項）：差值都是 0。我用的引擎、資料、窗格、20 條路徑設定和原研究相同，自寫的名單產生在每個訊號列都和原研究的改動檔數完全吻合，所以浮點數逐位相同。這表示 PREREG 的規則文字夠明確，從文字就能重建出同一套名單。只有兩處要靠 data_check 校準才能確定（見「方法」），PREREG 本身沒寫死。
2. **隨機換股對照（唯一不同）**：
   - 原研究沒寫隨機設計和種子。我的主設計是：每月隨機剔除和 SWAP_P2 相同檔數的 F1，再從 L_MA 第 11～20 名中 RET20 > 10% 者隨機遞補相同檔數。
   - 20 次抽樣的中位數受少數大贏家（例如 3047、6442）是否被抽中影響很大，換種子就會差 2～3 個百分點：種子 1 是 34.97%、贏 16／20；種子 20261116 是 37.51%、贏 9／20。
   - 抽 200 次後，驗證窗中位數 35.28%（原研究 34.88%），SWAP_P2 贏隨機的比例 74%（原研究 16／20＝80%）。
   - 另外兩種設計也一樣：補滿 10 檔時中位數 34.02%、贏 17／20；不看 RET20 時 33.85%、贏 16／20。
   - 所以原研究「依共振挑比隨機換略好，但換股本身就虧」的描述可以重現，只是「贏 16／20」這個精確數字要看種子。這一項是事後描述，不影響判定。

## 檔案（都在 s21_industry_resonance/replicate/）

- `rep_s21_lib.py`：PIT 產業查表、共振特徵、規則名單產生（自寫迴圈＋A1 assert）、重新起跑。
- `rep_s21_prep.py`：第 0 步核對，對照 data_check.json（不算報酬）。
- `rep_s21_run.py`：主程式，輸出 `results_rep.json`。內容包括驗收、訓練、自行凍結、驗證、全期描述、隨機對照，以及 1,200 個路徑數。
- `rep_s21_rand_sens.py`：隨機對照的設計和種子敏感度，輸出 `results_rand_sens.json`（已併入 results_rep.json）。
- 原研究的檔案都沒有改動。沒有 git commit 或 push。

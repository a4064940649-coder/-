## 6. 我們學到什麼

**被支持的機制或事實**
- **前瞻協定可以做到在模型內全格合格**：G8P-1 原樣有 95 格超標（最高 16.0%），V1 是 0 格（最高 4.68%），差異大於 MC 誤差。o14 的方法教訓 2、3（OC 掃 σ 區間、判定線用較差成本）確實有效。

**被否定、下修或無法判斷**
- **「主策略跨三段都贏」：下修。** 第一段改標「未證實」，最不利口徑下 t 只剩 0.51。
- **「G8P-2 補上了成本模型錯誤的缺口」：只部分成立。** 保護只有約 0.25～0.33pp／月的邊際，零股成本校準永遠做不到。
- **「凍結後就不能回改」：只部分成立。** git 已推上遠端，但判定器只看本機 committer date；status 輸出沒有雜湊鏈；open 月份可以不計作廢地被剔除。
- **2009-12～2011-12 下市股的月營收公開封存：本次 70 次搜尋、9 個 repo 內找不到**（不是「不存在」）。

**方法教訓（下一輪起寫進 PREREG 範本）**
1. **OC 的 DGP 要包含正序列相關**（AR／MA，至少到歷史 ρ 的上界），不能只用 iid 和單一子期間的 bootstrap。
2. **studentized 分母要同時套相依膨脹係數**，例如 c·max(σ_d, s_n)。
3. **判定輸出也要只能追加**：status 輸出串成雜湊鏈，已判定的狀態要鎖定；open 月份要有時限，並計入作廢。
4. **外部錨定要有第三方時間戳**：遠端 push 紀錄，或公開時間戳服務。判定器要比對遠端，不能只讀本機。
5. **共用引擎碰到下市股，一定要同時報「凍結」和「收購或換股對價」兩種口徑**，否則會高估損失。
6. **遮罩與分類一律 PIT**：產業、金融遮罩要用當時的分類，否則下市股會漏進股池或被誤排除。
7. **文件以凍結協定為準**：FINDINGS 和協定的缺陷清單要逐條對齊，凍結前做一次交叉比對。

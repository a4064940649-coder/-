# ACCEPTANCE：G6 第三階段驗收規則（草案，待總監凍結）

對象：依 `SPEC_v2.md`／`SPEC_v2.json` 重建主策略 ALLPIT_REAL 名單與 V7X 可執行數字的三位複製員——**A（名單）、B（引擎）、C（覆核）**——以及一位**目標保管員 K**。
依據：`original_o20/DIRECTOR_REPORT.md` 第 6 節方法教訓 1、2、3、8、10 與第 7 節題 2。
本文件裡標「〔待裁定〕」的數值或做法是撰寫員的提案，總監凍結前可改；凍結後不得改。

---

## 1. 角色與獨立性

| 角色 | 工作 | 限制 |
|---|---|---|
| K 保管員 | 以**原程式**重產驗收目標並封存；之後只負責回答「是否一致」與提供第一個分歧位置 | 不得把目標內容傳給 A、B；不寫複製程式 |
| A 名單 | 只靠 SPEC v2 與資料檔，從頭重建紙上與 V7X 的 REAL 名單 | 見第 2 節 |
| B 引擎 | 只靠 SPEC v2 與資料檔，從頭寫 V7X 可執行引擎與紙上引擎、統計 | 見第 2 節 |
| C 覆核 | 揭盲、比對、追第一個分歧、判定；用自己寫的統計程式重算 A／B 的輸出 | 不得與 A、B、K 為同一 session；不寫名單或引擎 |

1. A、B、C、K 必須是**四個不同的 session（或由總監層分派的不同子代理）**；每個角色記錄 session／agent id 與開始時間（UTC）。同一 session 兼任兩個角色，其結果一律不計（方法教訓 1）。
2. 任一角色若在凍結自己的程式前接觸到第 2.2 節的禁讀內容，必須立刻揭露；該角色的結果降為「不計」。

## 2. 資訊隔離

### 2.1 A、B 可以讀的東西
- `o_g6_spec_v2/SPEC_v2.md`、`o_g6_spec_v2/SPEC_v2.json`（〔待裁定〕是否先產生「盲版」，見第 8 節第 1 點）。
- SPEC v2 第 1 節列出的資料檔（D-01～D-10）：價格面板、營收、處置清單、下市與併購表、名稱檔、時間戳檔、p_delay.json、model_spec7.json、cpi_tw.json、jscan_end_days.json、0050 與加權指數日曆。這些是資料，不是程式。
- B 另可讀：K 封存的「官方名單」（只有名單，沒有任何報酬或淨值），用於 Track E（第 4.2 節）。A 不可讀。

### 2.2 A、B 不得讀、不得 import 的東西
- **任何研究員或先前複製員的 .py**（包含但不限於 pclib、avail、o18lib、v7x_lib、v2_core、ia_core、v4lib、o3_core、drj_core、st_core、v7env、cz_engine、cz_v7x、x_data、x_exec、x_stats、x_ideal、fslib，以及各題的 replicate_*、review_*、k_target、b_exec 內的程式）。
- **目標數字與目標名單**：所有 FINDINGS.md、DIRECTOR_REPORT.md、results.json、iterations.json、explore.json；`o_g6_spec_v2/AMBIGUITY_LOG.md`（內含正式數字）；`o_g6_allpit_list_trace_stage2/out/`、`integrate_o18～o20/data/`、`o_exec_engine_rewrite_v7x/out/`、`main_v2/navs_*.parquet`；`plans_j7.csv`、`plans_ab7.csv`、`plan_*.csv`；K 的封存目標（B 的 Track E 名單除外）。
- **研究員程式產生的衍生快取**：`o_exec_engine_rewrite_v7x/data/x_cache.npz`、scratchpad 內任何 npz／pkl（含 `rep_o19/`）。
- 任務文字、PREREG 文字都不得出現正式數字（o20 的污染來源之一就是任務文字本身含目標數字）。

### 2.3 稽核
- 全部程式以 `python3 -I -B` 執行。
- 每支程式開頭安裝 `sys.addaudithook`，把 `open` 與 `import` 事件寫到 `logs/`；另做靜態 import 掃描。C 核對紀錄中沒有第 2.2 節的路徑。
- A、B 在交件前把自己的程式與輸出檔的 sha256 寫成凍結清單；C 揭盲前先核對 sha256。**凍結後不得再改**；揭盲後的任何修正另列「事後修正版」，嚴格版為主欄，事後修正版不算重現（o20 裁定）。
- A、B 可以在凍結前自行迭代，但只能用不含目標的閘門（例如內部一致性、SPEC 裡的結構性計數）；迭代版本數要揭露。

## 3. 目標的產生與封存（K）

現況：正式 V7X REAL 名單（3 變體 × 13 j × 20 seeds）已不在磁碟上。所以在 A、B 開工**之前**，K 要：

1. 以原程式（只讀 import，不修改）重產：
   - 紙上名單：ALLPIT_REAL_{opt,p90,carry} × {M1_paper, M2}，245 個訊號日。
   - V7X 名單：REAL_{opt,p90,carry} × j 0…12 × seed 0…19 × {DM_BASE, M2}。
   - V7X 每格每個 (變體, j, seed) 的日淨值，以及 20 seeds 平均後的逐 j 淨值：七格（100 萬一般、100 萬壓力、300 萬一般、1,000 萬一般、30 萬標準、30 萬 wholelot、30 萬壓力）× 兩種遮罩。
   - 紙上逐窗報酬與日淨值：三變體 × {一般, 壓力} × 兩種遮罩。
2. 核對重產結果等於既有正式表：紙上名單 sha 等於 `k_paper_stats.json` 的 lists_sha；V7X 基準七格對 integrate_o19／o20 正式表最大差 0.0（o20 整合已做到）。不相等就停下來回報總監，不得開始複製。
3. 把名單與淨值**壓縮後存進研究資料夾**（不得只放 scratchpad；方法教訓、DR20 第 7 節題 2），寫 sha256 清單，權限上不讓 A、B 讀取。
4. 另存一份「Track E 用官方名單」（只有 variant, j, seed, signal, exec, picks 欄），交給 B。

## 4. 比對項目

### 4.1 名單層（A）
逐槽比對（槽＝訊號日 × 股票）。主判準：**逐槽完全相同**。

| 項目 | 比對對象 | 回報 |
|---|---|---|
| A-P | 紙上 ALLPIT_REAL_{opt,p90,carry} × {M1_paper, M2} | 相同槽數／總槽數、逐日 Jaccard 平均、分 2006～2012／2013～2018／2019 起三段；放回槽（屬於放回集合 A 的入選槽）另算一次 |
| A-X | V7X REAL × 13 j × 20 seeds × {DM_BASE, M2} | 同上，另按 (變體, j) 分列；訊號日與成交日是否逐筆相同；MC 抽樣是否逐 seed 相同 |

- 不相同的槽逐一列出（日期、換出、換入），由 C 對照 SPEC 條號歸因。
- 名單不是逐槽相同時，其「實質影響」不由 A 自己算：由 K 把 A 的名單餵進**原引擎**，C 依第 5 節的三層比對量（名單差的影響）。

### 4.2 引擎層（B）
- **Track E（引擎單獨）**：K 的官方名單 × B 的引擎，對 K 的官方淨值。七格 × 三變體 × 兩種遮罩。除第 5 節的統計比對外，另做逐筆比對：同一份名單下，B 與原引擎每檔每日的成交股數與現金，找出第一個不同的（日期, 股票）。
- **Track P（紙上引擎）**：K 的官方紙上名單 × B 的紙上引擎，對 K 的逐窗報酬。
- **Track L（端到端）**：A 的名單 × B 的引擎，對 K 的官方淨值。這一條才是「只靠規格重建正式數字」。

### 4.3 統計層（C）
C 用自己寫的統計程式，從 A／B 的輸出與 K 的封存淨值重算全部指標，不沿用 B 的統計程式，也不沿用研究員的。

## 5. 三層比對與門檻

### 5.1 指標
V7X 每格、每個放回變體都算下列指標（定義見 SPEC v2 S-01～S-04）：
- 全期超額（pp）、全期對 0050 t、2019 起年化（%）、2019 起超額（pp）、三段超額（pp）、最大回撤（pp）。
- j 彙總：中位數與 p10。

紙上每個變體 × 成本 × 遮罩（S-05）：全期日曆年化（主口徑）、ia 年化（並列）、全期超額、t、三段超額、拿掉最好 3 年 t。

### 5.2 三層（V7X）
令 x_j＝複製值、y_j＝目標值（j＝0…12），d_j＝x_j − y_j。

| 層 | 定義 | 門檻〔待裁定〕 |
|---|---|---|
| L1 j 中位數 | median(x) − median(y) | |·| ≤ 0.1pp；t ≤ 0.05 |
| L2 逐 j 平均 | mean(d_j) | |·| ≤ 0.1pp；t ≤ 0.05 |
| L3 逐 j 最大絕對值 | max |d_j| | ≤ 0.1pp；t ≤ 0.05 |

另外必報、不設門檻但會影響判定文字：
- **中位 j 是否換人**：取得中位數的 j（13 個值排序第 7 個的 j）在複製與目標是否相同。
- **最差變體是否換人**：逐格逐指標取 opt／p90／carry 最小值時，最小者在複製與目標是否相同；逐格最差後的值也要比（門檻同 L1）。
- p10 的差。
- 2019 起各層另列（起點口徑照 S-02 主欄；三段表的口徑並列）。

只用 L1 宣稱「已歸因」「在門檻內」一律不算（方法教訓 3）。

### 5.3 紙上
- 全期日曆年化、ia 年化、超額、三段超額：|差| ≤ 0.1pp；t 與拿掉最好 3 年 t：|差| ≤ 0.05。
- 另報：逐窗報酬最大絕對差、逐年報酬最大絕對差、拿掉差異貢獻最大一窗後的差（方法教訓 10）。

### 5.4 判定

| 結果 | 條件 |
|---|---|
| 通過 | 該項所有格、所有變體、所有指標的 L1、L2、L3 都在門檻內；中位 j 與最差變體沒有換人，或換人但逐格最差值仍在門檻內且已說明 |
| 部分 | L1、L2 在門檻內，但有格的 L3 超過；每一個超過的 (格, 變體, j) 都要追到第一個分歧並歸因到 SPEC 條號 |
| 失敗 | L1 或 L2 有任一超過門檻 |
| 無法測試 | 因資料或規格缺口而做不出來；要寫明缺什麼 |

**G6 通過**必須同時成立：
1. A-P、A-X 逐槽相同；或不相同但名單差的影響（第 4.1 節末）三層都在門檻內，且每個不同槽都已歸因。
2. Track E、Track P、Track L 都「通過」。
3. 角色獨立（第 1 節）、資訊隔離（第 2 節）稽核無違規。
4. 主欄是凍結的嚴格版；事後修正版不得用來補足任何一項。

## 6. 揭盲後的處理

1. C 一次揭盲。分歧出現時，C（需要原引擎逐筆紀錄時由 K 提供）找出第一個不同的（日期, 股票）或（訊號日, 槽），以原始資料與 SPEC 條文裁定，結果只有四種：
   - **複製端錯**：照嚴格版計分；事後修正版並列、不算重現。
   - **規格錯**（SPEC v2 沒有正確描述程式）：發 SPEC 勘誤（v2.1），該項由**新的 session** 重做；原 session 的結果不計。
   - **規格缺口**（SPEC v2 沒寫到）：同上，補進勘誤。
   - **原引擎錯**（程式偏離其應有規則）：若對正式格的影響 > 0.1pp（任一層），依 DR20 規則取代正式數字並附歸因；否則加註。取代前要由不同 session 覆核。
2. 有疑義取不利方向；不利端與嚴格版並列時，嚴格版為主欄。
3. 複製成功（Track L 通過）且 M2 各格也通過時，依 DR20 裁定正式改採 M2。

## 7. 其他紀律

- `o_g8p2a_protocol_addendum/`、`live_tracking/main_forward/`、`o_forward_infra_live/` 只讀；題目開始與結束各做一次 sha256 快照比對；不得呼叫 G8P-2a 判定器。
- 年化口徑在 PREREG 寫死：V7X 用日曆年化（S-02）；紙上以日曆年化為主、ia 並列（S-05）。報告標題必須用凍結口徑（方法教訓 8）。
- 重疊樣本：13 個 j 不是 13 個獨立樣本，判定文字不得把 13 個 j 當獨立證據。
- 所有名單、逐 j 淨值、逐筆追蹤檔壓縮後存研究資料夾；scratchpad 只放可重產的中間檔。
- PREREG 先寫好並算 sha256，早於任何複製程式的第一次執行。

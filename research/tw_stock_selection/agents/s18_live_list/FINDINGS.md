# S18：現行策略的每月名單產生器＋前瞻紙上追蹤

> 這一題不回測新規則，只把現行策略（S10 E0＝XQ 20＋21 號預設、W10_70）做成每月可以直接跑的名單產生器，並定好紙上追蹤的紀錄格式。
> **這是紙上追蹤，不下真錢單。** 產生器只讀公開資料、只輸出名單與假想下單，不連任何券商。

## 1. 結論

- 產生器 `live_surge/make_list.py` 和 S10 E0 回測**逐檔相同**：
  - 129 個訊號月（2016-02～2026-10）的訊號日、L_MA 前 20 名（含順序）、SURGE、F1 名單全部相同（SURGE 最大差 0）。
  - 以回測當時的持股為輸入，E0 賣出名單 129／129 個月相同。
  - 指定的 2025-09、2026-08 用命令列端到端跑，F1、賣出、前 20 名都相同。
- 買進名單（F1 扣掉已持有、補滿空位、跳過次日開盤漲停）和回測實際買進：2020-10-26 零股上路後 72／72 個月相同。之前有 33 個月不同，都是「只能整張買」造成的（32 個月是一張的成本超過每檔目標金額，1 個月是整張進位或成交值上限）。
- **2026-11 名單**：訊號日 2026-11-11，F1 只有 **1802 台玻** 一檔。
  - 這個月 L_MA 第 10 名的 SURGE 是 3.10，比 129 個月的中位數 2.52 高很多；前 10 名中只有台玻前 20 日漲超過 10%。
  - 以「上月已持有回測持股」為例：賣出 6213、3416、3037、2492（跌破季線）和 2355（掉到第 27 名）；續抱 3311、2480、4938；買進 1802。
- 資料要注意：研究中心原本的月營收檔 tw_revenue.csv 只到 2026-09。2026-10 營收改用官方日 K 倉庫裡的公開資訊觀測站彙總表，和 tw_revenue 重疊的月份逐筆比對過（見第 2 節）。
- 2026-11 名單是 2026-11-15 才產生的，成交日 11/12 已經過了，**不算前瞻**。真正的前瞻紙上追蹤從 **2026-12** 開始（預估訊號日 2026-12-11）。

## 3. 產生器用法

檔案：`live_surge/make_list.py`（單一檔、只用 numpy／pandas／git，一律 `python3 -I -B`）。

```bash
# 0) 取得最新官方資料（建議放暫存區；不要動研究中心的 raw 封存）
git clone -q --filter=blob:none --no-checkout --depth=1 https://github.com/jb7k6295r7-bot/tw-stock-data <暫存>/tsd

# 1) 產生名單：空倉起始、總資產 100 萬
python3 -I -B live_surge/make_list.py list --month 2026-11 --total 1000000 \
    --repo research/tw_stock_selection/raw/jb7k6295r7-bot_tw-stock-data --repo <暫存>/tsd \
    --rev-cutoff 2026-11-11T14:00:00Z --out-prefix lists/2026-11

# 2) 有持股：holdings.csv 欄位「代號,股數」，0050 也寫一列（含底倉）；底倉股數另外給
python3 -I -B live_surge/make_list.py list --month 2026-11 --holdings holdings.csv --cash 0 --base-shares 1995 \
    --repo ... --repo <暫存>/tsd --out-prefix lists/2026-11_mine --paper-log paper_log.csv

# 3) 成交日之後：填實際開盤價、漲跌停、回測會不會成交
python3 -I -B live_surge/make_list.py fill --paper-log paper_log.csv --repo ... --repo <暫存>/tsd

# 4) 算出成交後的紙上持股，給下個月用
python3 -I -B live_surge/make_list.py holdings --paper-log paper_log.csv --month 2026-11 --out hold_2026-11.csv
```

輸入：
- `--month`：訊號月份。2026-11 用 2026-10 營收。
- `--total`：總資產。
- `--holdings`：目前持股，可不給。
- `--cash`：現金。
- `--base-shares`：底倉 0050 的帳上股數。不給時視為新開始，底倉＝總資產 30%。
- `--repo`：日 K 和營收的 git 倉庫，可以給多個。後面的倉庫補前面沒有的日子；同一個 blob 沿用前面本機已有的那份。
- `--rev-cutoff`：補充營收的時點截止。

輸出：`<prefix>.csv`、`<prefix>.md`、`<prefix>.json`，內容有：
- 當月訊號日、預期成交日。
- L_MA 前 20 名表：名次、代號、名稱、SURGE、RET20、是否在季線上、距季線、60 日均成交值、收盤、是否 F1。
- F1 買進名單：每檔目標金額、建議股數、買不到一半就不買的判定。
- 持股的賣出／續抱，附原因：跌破季線、名次掉出前 20、沒有 SURGE、不在股池、創新板、非上市、下市。
- 底倉 0050 ±10 個百分點檢查：衛星占比、偏離幾個百分點、要不要重設底倉、要不要減碼。
- 0050 要買或賣幾股、換股後 0050 總股數、底倉股數。

資料不夠時不猜，回傳「資料不足」和原因，例如「日 K 最新到 2026-11-13，還沒有 2026-12-10（含）之後的交易日」。

規則和回測逐條相同（程式開頭有完整說明）：
- 金額：每檔＝衛星 ÷ 10，最多 10 檔，依 SURGE 由大到小買。
- 買得到的金額不到目標一半就不買。2020-10-26 起可以買零股，之前只能整張。
- 錢不夠先用現金，再賣 0050（W10_70 不鎖底倉）。
- 剩下現金 ≥ 2 萬就買 0050。
- 衛星占比超出 60%～80% 就把底倉重設成總資產 30%。偏低時只改帳；偏高而且現金加 0050 不夠時，依市值等比例減碼。

和回測不同的地方（只影響「建議股數」，不影響名單）：
- 價格用訊號日收盤估，回測用次一交易日開盤。開盤跳空時，請用「目標金額 ÷ 開盤價」重算。例如 2026-11 的台玻開盤比收盤高 5.2%。
- 回測單日最多買當天成交值的 5%。產生器在目標金額超過 60 日均成交值 5% 時只出警告。

## 4. 驗收結果（VALIDATION.json）

做法：
- `validate_ref.py` 用 S10 的 s10lib（不改）重建 E0 訊號，並跑 E0｜W10_70 主跑。主跑 2019 起 48.13%、全期 34.08%、最大回撤 −33.40%，和已發表的數字相同。
- `validate.py` 用 make_list 的資料層和計算逐月對照。

| 項目 | 內容 | 結果 |
|---|---|---|
| V1 | 訊號日、L_MA 前 20 名（含順序）、F1（含順序） | **129／129 個月相同**，SURGE 最大差 0 |
| V2 | 以回測持股為輸入，E0 賣出名單 | **129／129 個月相同** |
| V3 | F1 扣已持有、補滿空位、跳過次日開盤漲停 → 對回測實際買進 | 零股上路後 **72／72**；全期 96／129，33 個月的差異都在 2020-10-26 以前，是整張限制造成的 |

## 5. XQ 對帳說明

使用者在 XQ 用 20＋21 號跑出的當月名單，和本產生器不同時，常見原因如下，照順序檢查。

**常見原因**
1. **SURGE 門檻和名次不同（最常見）**：研究中心用「L_MA 前 10 名」和「前 20 名」，XQ 用固定門檻 `MinSurge` 2.5、`ExitSurge` 2.0 近似。
   - 2026-11 就是例子：第 10 名 SURGE 3.10、第 20 名 2.67，都比門檻高很多。
   - XQ 20 號（`MinSurge` 2.5、`MinRet20` 10）會選出 **5 檔**：1802、6108（第 11 名）、9933（第 12 名）、3029（第 18 名）、2355（第 27 名）。研究中心只買 1802。
   - 改 `MinSurge` 3.0 剩 3 檔（1802、6108、9933）；改 2.2 會多出 6446（第 31 名）。
   - XQ 21 號 `ExitSurge` 2.0 會讓 **2355 敬鵬**（SURGE 2.53、第 27 名）續抱，研究中心照名次賣出。這個月有 36 檔 L_MA 股票的 SURGE ≥ 2.0。
   - 對帳方法：XQ 跑 20 號時把 `MinRet20` 改成 −1000、`MinSurge` 改成 −999，依 SURGE 排序，數出第 10、20 名，和產生器的 L_MA 表比。
2. **營收欄位更新時點**：XQ 的「月營收」欄位在訊號日當天收盤後是否已經包含全部公司，需要確認。
   - 10 日落在週末或假日的月份，XQ 的訊號日就是營收期限當天，有些公司晚上才公布。研究中心那幾個月的訊號日是期限後的下一個交易日。
   - 2026-11 兩邊都是 11/11，沒有這個問題。但有 9 檔金融股的營收到 11/12 才被公開倉庫抓到；它們不影響這個月的名單。
   - 營收被更正時，XQ 可能用更正後的數字。tw_revenue 和公開資訊觀測站的數字每月約有 2～8 家上市公司不同。
3. **股池篩選**：
   - 只看上市。
   - 排除創新板，也就是股名結尾是「-創」或「-KY創」的股票。
   - 研究中心的營收檔沒有 KY 股，所以 KY 股不會進名單。
   - 60 日均成交值：研究中心用官方日 K 的成交金額，無成交日算 0，而且要連續 60 天都在日 K 內；XQ 用收盤 × 成交量（張）近似。
   - 收盤 ≥ 10，看訊號日當天的原始收盤；當天沒成交不算。
   - 91 開頭的 TDR 不算。
4. **還原價**：研究中心的季線和 RET20 用「含息日報酬連乘」的還原價。
   - XQ「還原日線」的還原方式（含不含現金股利、減資）若不同，貼近季線或 RET20 剛好在 10% 附近的股票會進出不同。
   - 產生器輸出的「距季線」和 RET20 可以直接拿來比。
5. **持股不同**：
   - XQ 回測的持股會因為進出差異越差越多，下個月的賣出名單自然不同。
   - 開盤漲停買不到、買得到的金額不到一半不買、「最多 10 檔、滿了不買」，這三條 XQ 能不能設也會造成差異。

**檢查步驟**
1. 確認兩邊的訊號日相同（產生器 JSON 的 `sig_date`；XQ 是第一個日期 ≥ 11 的交易日）。
2. 拿 XQ 名單逐檔查產生器的 L_MA 表（`lists/<月>.csv`）：
   - 不在表上 → 查股池（上市、創新板、均成交值、收盤）或季線。
   - 在表上但名次 > 10 → 門檻近似造成的。
   - RET20 ≤ 10% → 還原價差異。
3. 比 SURGE 數值：差很多 → 營收欄位不同。抽查該股近 37 個月營收，產生器的 JSON 只有算好的 SURGE，原始營收在 tw_revenue.csv 和公開資訊觀測站。
4. 賣出名單不同 → 先確認持股相同，再看是不是 `ExitSurge` 2.0 和第 20 名分數的落差，2026-11 的第 20 名是 2.67。
5. 差異記在紙上追蹤紀錄的「說明」欄，累積幾個月後再判斷 XQ 回測和研究中心回測的差距來源。

  - 台玻 11/12 開盤 80.7，比 76.7 高 5.2%，沒漲停，回測會買到。
  - 五檔賣出股開盤都沒跌停，回測會賣掉。
  - 0050 開盤 103.5。

## 7. 前瞻紙上追蹤

**紀錄格式**：`PAPER_LOG_TEMPLATE.csv`，一列一個動作。範例見 `lists/2026-11_paper_log_example.csv`。

| 欄位 | 內容 | 誰填 |
|---|---|---|
| 紀錄日、訊號月份、訊號日 | 產生名單的日期、月份、訊號日 | 產生器 |
| 動作 | 買進／賣出／續抱／買進0050／賣出0050／0050合計／現金餘額／底倉記帳 | 產生器 |
| 代號、名稱、股數 | 建議股數；現金餘額這一列的「股數」是金額（元） | 產生器 |
| 參考價_訊號日收盤 | 估股數用的價格 | 產生器 |
| 預期成交 | 訊號日次一交易日開盤 | 產生器 |
| 實際開盤價、漲跌停檢查、開盤對參考價pct、回測會不會成交 | 開盤漲停不買、開盤跌停順延賣（回測規則） | `fill`（事後） |
| 實際成交價、實際成交股數 | 真的照著做的人自己填；純紙上可以空著 | 使用者 |
| 與回測差異 | 有填實際成交時，`fill` 算「成交價對開盤 %」和「股數差」 | `fill` |
| 說明 | 名次、出場原因、底倉檢查結果，也可以寫 XQ 對帳差異 | 產生器／使用者 |

**每月怎麼更新**（不需要另外排程；研究中心之後的每日排程每個交易日呼叫一次即可）：
1. 更新資料：重新 clone（或 fetch）官方日 K 倉庫到暫存區。
2. 跑 `list --month <本月>`：
   - 訊號日資料還沒到，或營收涵蓋率 < 95% → 回傳「資料不足」，什麼都不寫。
   - 第一次出現「有訊號」→ 加 `--paper-log` 寫進紀錄。同一個訊號月份已經寫過就不會重複寫。
   - `--holdings`、`--base-shares`、`--cash` 用上個月 `holdings` 子命令算出的紙上持股。
   - 2026-12 的起點可以用 `lists/2026-11_paper_log_example.csv` 算出的持股，或空倉 100 萬。
3. 每天跑 `fill`：成交日的日 K 一到，就把實際開盤價和「回測會不會成交」填好。
4. 成交日之後跑 `holdings --month <本月>`，得到下個月要用的持股 CSV、底倉股數、現金。
   - 開盤跌停沒賣掉的股票會標成「賣出順延」，要人工每天追蹤，回測是順延到第一個能賣的交易日開盤。
5. 建議訊號日當晚 22 點後再跑一次，加 `--rev-cutoff <當天 14:00 UTC>` 比對。前 20 名或 F1 不同時，在「說明」記下來。

## 8. 限制

- 2026-10 營收來自公開資訊觀測站彙總表，不是研究中心回測用的 tw_revenue.csv。兩者重疊月份 99% 以上相同，但不是同一個檔案。tw_revenue.csv 之後更新時，應該重跑 2026-11 確認。
- 產生器依賴官方日 K 倉庫要有最新資料。研究中心的 raw 封存目前停在 2026-10-30，產生器不會自己更新它；本題的新資料放在暫存區，題目結束後已刪除，要重跑請照第 3 節重新 clone。
- 建議股數是用訊號日收盤估的，實際成交價是次一交易日開盤；單日 5% 成交值上限只出警告，不會自動砍股數。
- 「上月已持有回測持股」是把回測持股等比例縮小的示範，不是真實帳戶。回測期末是 2026-10-22，持股估值用 11/11 收盤。
- 2026-11 名單是事後產生的（成交日已過），只當示範；前瞻追蹤從 2026-12 起算。
- 驗收的 V3 只比「買哪幾檔」，不比股數：回測股數取決於當天的淨值和開盤價。
- XQ 腳本仍未在 XQ 編譯或回測；第 5 節的 XQ 名單是用同一份資料模擬門檻算出來的，不是 XQ 的實際輸出。
